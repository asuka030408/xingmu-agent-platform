# 星幕设备：文档问答、权限与并发设计

状态：早期扩展设计稿。安全边界、事务预订与并发控制已按 `security-and-concurrency.md` 落地；员工登录和 RAG 暂不实施。下文涉及登录、文档库和审批的内容仅供以后接入真实企业场景时参考。

## 目标

让员工在同一个入口询问设备、项目、说明书和合同，同时让每个回答有依据、每个员工只看到有权看的内容、每次正式预订都不会重复占用设备。

第一期沿用现有 PostgreSQL 和 Python 服务。Agent 保持一个，不拆成多 Agent。业务数量由已定义的查询工具计算；文档问题由检索工具找出处，再交给回答模型组织语言。

## 模块

| 模块 | 职责 | 第一版交付 |
| --- | --- | --- |
| 员工身份与权限 | 登录后识别员工、岗位、负责项目和可见合同；在每个工具调用前检查权限 | 员工、岗位、项目范围；默认无权限即不可见 |
| 文档库 | 保存说明书、维修手册和合同的版本、归属、状态及原文件 | 上传、解析、审核、发布、作废 |
| 文档检索与 RAG | 先按权限和版本过滤，再按设备型号、项目、标题、关键词检索相关段落；回答附出处 | 回答展示文件名、版本、页码或段落 |
| 合同条款台账 | 将影响排期的合同条款转成经过人工确认的字段 | 交付时限、验收条件、特殊设备要求、违约约定及原文位置 |
| 排期服务 | 继续用数据库计算设备可用量、维修、预订、跨仓和外租缺口 | 读取已批准的合同条款作为约束 |
| 操作审批 | 将建议变为待确认调拨/预订申请，由负责人批准 | 申请、审核、拒绝、执行、状态查询 |
| 运行保障 | 控制请求量、超时、连接数；记录查询和操作轨迹 | 健康检查、日志、告警、备份恢复演练 |

### 文档进入系统

上传文件 → 限定格式与大小并扫描 → 提取文本 → 切成带页码的段落 → 标注客户、项目、设备型号、版本、生效时间和权限 → 资料负责人审核 → 发布。旧版保留供追溯，但默认查询只使用当前有效版。扫描件需要 OCR 后再由人核对；识别失败的段落不发布。

说明书可以直接供 RAG 回答使用。合同的原文也可检索，但影响“能否交付”的条款，先由合同负责人核实并写入结构化台账；排期服务只读取已批准条款。回答合同问题时同时显示条款原文和版本。

### 一次问题怎样走

| 员工问题 | Agent 使用的工具 | 返回内容 |
| --- | --- | --- |
| “上海仓还剩多少 LED-P3？” | 库存查询 | 数据库实时数量与更新时间 |
| “LED-P3 的吊装要求是什么？” | 文档检索 + 回答模型 | 说明书摘要、版本、页码 |
| “客户 A 合同要求提前几天交付？” | 有权限的合同检索；若有已批准条款则核对台账 | 条款、出处与是否经过确认 |
| “这个活动能交付吗？” | 项目、库存、维修、预订、已批准合同条款 | 交付结论、缺口、约束依据 |
| “帮我预订这些设备” | 生成申请 → 人工确认 → 预订接口 | 成功编号或明确冲突原因 |

## 权限和安全边界

1. 网页登录后，把员工身份传给每一次后端请求；后端按岗位和项目范围过滤业务数据及文档。界面隐藏按钮只是提示，真正的权限检查在 API 和数据访问层。
2. 仓库岗位可查设备与出入库；维修岗位可查说明书和维修；销售只看自己负责项目的合同；调度岗位可看跨项目设备计划；审批人可确认调拨和预订。合同金额和客户资料另设权限。
3. 文档检索在检索前过滤权限，文件下载也再次检查权限。Agent 只能调用登记过的工具，不能把检索到的文档文字当作新的系统指令。
4. 查询工具保持只读。预订与调拨使用单独的写入接口和数据库角色，接口再次检查审批状态；所有操作记录员工、时间、原方案和最终结果。
5. 问题和答案日志按敏感级别脱敏并设保留期。密钥由服务端安全配置提供，不进入网页、文档索引或回答内容。

## 并发控制

**同时提问**：正式 Web 服务处理多个请求，数据库连接池限制连接数；查询设置超时和结果上限，长文档解析交给后台任务。高频访问限流，避免一个用户占满服务。

**同时预订**：页面展示的是建议，正式确认时要在同一个数据库事务中重新检查设备状态和占用时间，再写入预订。数据库为“同一设备、时间段不能重叠”设置排斥约束；若另一名调度员已经订走设备，本次提交返回冲突并重新生成方案。重复点击同一申请使用唯一请求号，保证只执行一次。PostgreSQL 的范围与排斥约束适合表达这条规则。[官方文档](https://www.postgresql.org/docs/18/rangetypes.html)

## 分步实施

1. **先让信息可信**：接真实设备与订单数据，建立员工登录、数据权限、文档库和说明书问答。此阶段只读。
2. **再让规则可信**：合同条款审核入台账，排期服务使用这些条款，逐单与调度员结果对照。
3. **最后让操作可执行**：加入申请、审批、事务预订、重复请求保护、冲突提示，并完成备份恢复和并发压测。

## 上线前的四个验收场景

- 无权查看客户 A 合同的员工，无论自然语言提问、直接调用检索接口还是访问文件地址，都拿不到合同内容。
- 说明书问答必须显示文件版本和页码；找不到可靠出处时明确说“未找到依据”。
- 两名调度员同时预订同一台设备的重叠时间，只能有一笔成功；另一笔收到冲突提示。
- 员工连续点击两次“确认”，系统只生成一笔预订，并能在审计记录中追溯操作人。

## 用一句话概括策略

先确定员工能看什么，再让 Agent 去查；数字由业务系统计算，文字从有出处的文件中找；任何真正占用设备的动作，都由人确认并让数据库做最后一道检查。
